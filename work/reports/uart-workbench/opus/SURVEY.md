## This proposal's structure / difference
- **Common shell vs module:** the Bench Light shell (header with UART-only service nav, SIM chip, connection count; two-part status bar) is module-agnostic. Everything UART lives in `#modUart[data-module=uart]`, which is the integration boundary for the eventual product UI. Other services stay out of the nav until each module exists (they are planned, not shown).
- **Workspace = tree of tab-groups:** every pane is a tab group (VS Code-like editor group) in a free binary split tree. Tabs drag by pointer between tab strips (ordered insert) or onto pane edges (new split). Keyboard and menu move alternatives exist.
- **One port, one tab:** opening, dropping, or picking an open session moves it instead of duplicating it. Aliases are unique. Each pane header shows alias · port · frame · state. Since REV3, input is typed directly into the real xterm terminal; there is no separate input row.
- **Macros are tools, not prompts:** a step table with `send`, `wait`, `delay`, variables and a hotkey. ▶ runs immediately (REV5; only missing variables open a small values dialog). Targets follow the REV6 rule: a 고정 override, otherwise the macro-panel scope 활성 / 연결된 모두 / 선택. Edit, duplicate and delete live in the ⋯ menu. A run strip inside each target pane shows step states. Stop aborts the pending wait or delay and sends nothing after. (Historical, pre-REV3: an input row with pinned chips and a confirm-before-run dialog — both since removed.)
- **Per-terminal theme:** the shell is light, and each terminal is dark by default with a per-tab light toggle that persists.

**Chosen interaction ([I], from the three sources above):**
- Two different jobs get two clearly labelled controls:
  - the toolbar **키 입력 대상** (typing, as with MultiExec/iTerm2 broadcast);
  - the macro panel **실행 대상**, `활성 | 연결된 모두 | 선택`, a SecureCRT-style send-to scope placed directly above the ▶ list, with a live recipient line (`연결된 모두 → mcu, aux, console (3) · 제외 debug(읽기 전용)`).
- The macro scope never changes typing, and the typing target never changes macros.
- **One resolution rule for every entry point** (sidebar ▶, pane macro menu, hotkey): a per-macro **고정** override (the migrated legacy target, labelled with a chip) wins, and the panel scope applies otherwise.
- The recipient set is fixed at launch, so sessions opened mid-run do not join. Reload resets the scope to 활성.
