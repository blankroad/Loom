## Behaviour
- Config (`config.rs`): home `LOOM_HOME` else `$HOME/.loom`. Daemon `LOOM_DESKTOP_DAEMON_BIN` (absolute, exact) else `loomd` next to the app exe (`Loom.app/Contents/MacOS/loomd`, via the QA externalBin contract). Optional `LOOM_DESKTOP_UI_DIR` (absolute). `LOOM_DESKTOP_STARTUP_TIMEOUT_MS` (clamped 1–120 s, default 20 s).
- Launch: the main window opens on the launch page. A `loom-connect` thread calls `loom_desktop_host::connect` (reuse, or start detached). The viewer URL must be on `http://localhost:<session.port>`, then the window navigates to it. The URL and token are never logged. Only pid, port, home and started/reusing are logged. Errors show the host crate's redacted Display text plus home and daemon path, with Retry.
- Once at `RunEvent::Ready`: `show()` + `set_focus()` on main. No other focus changes, no loops.
- **Connection ▸ Reconnect (⇧⌘R)** (review F1): clears the pinned port, sets Connecting, sends main back to the launch page (or recreates it), then runs a fresh connect + bootstrap. Also recovers from Failed.
- Navigation (`nav.rs`, review F2): top-level navigation loads only app assets, `about:blank`, or the exact `http://localhost:<port>` (no userinfo, not 127.0.0.1, not https). Everything else is **denied without spawning anything**. New-window requests: daemon origin → child app window with the same policy and shared cookie store; other http(s) → system browser via `/usr/bin/open` (one argv element, no shell); all else denied.
- Quitting or closing never stops the daemon: no kill or Drop in the app; the host spawns it detached.
- `e2e` feature (alias `qa-webdriver`): test-only in-app W3C WebDriver (official WebdriverIO Tauri embedded provider). It compiles only in **debug**: `e2e` + release hits a `compile_error!`. The server starts only if `LOOM_DESKTOP_QA_WEBDRIVER_PORT` or `TAURI_WEBDRIVER_PORT` is set. The crate source binds `SocketAddr::from(([127,0,0,1], port))`. It has no Tauri IPC permissions (default set empty) and reports results through WKScriptMessageHandler. Its navigate still passes our `on_navigation` policy.

## RX diagnosis (ROOT reopened after native QA fail-rx.png), result
**Root cause: the macOS console session is locked and the display is asleep.** Since 07:18:32 KST, `CGSessionCopyCurrentDictionary` shows `CGSSessionScreenIsLocked=1`, and `CGDisplayIsAsleep(main)=1` with 0 active displays. While locked, every window is occluded. WebKit then reports `document.visibilityState=hidden` and stops `requestAnimationFrame`. That held even for my window at layer 5 (always-on-top), measured as rAF 0×/s through WebDriver. The UART trace and terminal draw only in `scheduler.onFrame` (rAF), so they show "수신 없음" or blank. This also plausibly explains the CUA `cgWindowNotFound`, AX listing 0 windows and `screencapture` "could not create image". Data is **not lost**: `net/core.ts` keeps receiving and mirroring while hidden (visibility only drives presence and clock), and panels catch up on the first visible frame.

**Real UI bug found and fixed (ROOT-authorized, paths announced first):** `ViewerReporter.visible` started `true` and changed only on `visibilitychange`. A page that loads already hidden (locked screen, occluded window, background tab) never gets that event, so it reported `visible:1` to the daemon. Agents were then told `visibility: visible` (QA's `vis=visible`) while nothing rendered.
- `ui/src/shell/services.ts`: after registering the listener, call `vis()` once to sync the initial `document.hidden` (3 lines).
- `ui/src/shell/m1Shell.test.tsx`: two regression tests: loaded hidden → `net.visible=[false]` and presence `{visible:false}`; loaded visible → no presence change.
- Checks: `vitest run` **56 files / 624 tests passed**; `tsc -p tsconfig.app.json --noEmit` OK; `eslint` on both files clean. Shared `ui/dist` was **not** rebuilt (it would change QA's staged-UI identity). The fixed UI was built to `/tmp/loom-rx-ui` and served by the daemon through `LOOM_DESKTOP_UI_DIR` → `loomd --ui-dir`.
- Native result with the fixed UI (same locked session): `loom status` shows `viewers {subscribed:1, visible:0}` (before the fix: `visible:1`). `loom uart send` gives `meta.visibility: not_visible`. The device round trip still works (`expect ok: true`).
- For product bundles: the embedded UI only picks up the fix after `ui/dist` is rebuilt and loomd is re-staged (QA `stage-loomd.sh`, ROOT decision).
