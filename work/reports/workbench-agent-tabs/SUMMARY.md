# 두 탭 구성 — ROOT 권고

2026-11-14. 별도 foreground Opus(w1W)·Sol(w1X) 독립 조사/목업을 비교했다. 추가 요청 범위는 구성안과 DEMO이며, 실제 두 탭 제품 코드는 아직 변경하지 않았다. [Opus 목업](OPUS.html) / [Sol 목업](SOL.html), [Opus 설계](OPUS.md) / [Sol 설계](SOL.md).

추천은 **Opus의 밀도 있는 관찰 화면 + Sol의 실행 상태 모델**이다. 기존 서비스별 화면과 실제 엔진은 유지하고, 공통 헤더 아래 `통합 보기 | 에이전트 작업`을 둔다. 환경·연결·기록 상태와 하드웨어 STOP은 공통 헤더에 남긴다.

| 화면 | 기본 구성 | 유지해야 할 동작 |
|---|---|---|
| 통합 보기 | 좌측 서비스·인스턴스 체크 선택기 → 우측 기존 dock 분할 패널 | UART+CAN, CAN+UDS, 세 개 이상 및 UART 여러 포트 선택. 자유 분할/크기 조절/최대화. 이름 있는 구성 저장 |
| 에이전트 작업 | 좌측 요청별 목록 → 우측 현재 단계·실행 근거·결과 | 사용자가 요청한 task만, 진행/이벤트 대기/사용자 응답 대기/실패/완료. 탭 전환과 실행 수명 분리 |

## 통합 보기

- 선택은 서비스 이름에서 끝나지 않고 **서비스 → 세션 → 포트/버스/ECU/NIC → 뷰**까지 한다. 패널 제목에 별칭·실체·세대를 함께 표시한다.
- 기본 선택기에는 현재 사용 중인 인스턴스만 나온다. 새 연결을 자동 추가하지 않는다. 저장·선택해 둔 오프라인 구성원은 그 자리에 `연결 끊김 / 마지막 수신 / 남아 있는 기록`을 표시해 사용자의 배치를 보존한다. 연결되지 않은 별도 서비스를 새로 생성하지 않는다.
- 기존 Dock을 재사용한다. 선택 두 개는 좌우, 세 개 이상은 자동 격자로 시작하고 이후 사용자가 수정한다. 저장은 구성/필터/배치만 저장하며 장치 재연결·송신·작업 재실행을 일으키지 않는다.
- UART 두 포트와 CAN+UDS를 한 화면에 둘 수 있다. UDS의 실제 CAN/DoIP/EthDiag 바인딩은 설정된 경로로 표시하며 나란히 보인다는 이유로 연결 관계를 추정하지 않는다.
- 서비스 전용뷰를 열었다 돌아와도 통합 선택/배치가 유지된다. STOP 후 기록 접근 범위는 각 도메인의 실제 보존 능력을 따른다. 현재 브라우저 캐시와 영속 기록을 구분한다.

## 에이전트 작업

목록의 한 행은 하나의 사용자 요청이다. 제목, 대상, 현재 단계, 상태, 경과 시간, 마지막 확인 시각을 표시한다. 상세에는 요청 원문 → 명시된 계획 → 현재 단계/도구 실행 → 확인한 로그·이벤트 → 산출물/결과를 둔다. 정보량은 유지하되 실행 근거의 원문은 필요할 때 펼친다.

작업 상태와 통신 신선도는 분리한다. 예를 들어 `CAN 프레임 대기 · deadline 15:40`은 정상 대기이며, 연결이 끊기면 `마지막 확인 15:38 · 상태 확인 불가`를 함께 표시한다. RPC가 한동안 없다는 이유만으로 실패·정체로 판정하지 않는다. 진행은 근거가 있는 `2/4 단계 완료`로 표시하고 계획 변경 이력을 남긴다.

`작업 취소`는 해당 task의 취소 요청 → 실행자 정리/ACK → 취소 완료 순이다. 공유 실행자의 다른 작업을 프로세스 단위로 중단하지 않는다. 이미 실행한 명령과 산출물은 남는다. `하드웨어 STOP`은 기존 장치 안전 경로이며, task 취소와 별개다. 승인/질문은 실제 정책이나 필요한 입력이 있을 때만 표시한다.

핵심 기술 차이는 **기존 core.activity가 RPC 활동 요약이라는 점**이다. 요청별 Task/Step, runner 상관 ID, 명시 상태, 대기 조건, 결과·취소 ACK 및 snapshot/증분 이벤트 계약을 추가해야 실제 진행 상황을 정확히 보여줄 수 있다. 레이아웃 저장은 현재 LocalLayoutStore(localStorage)를 재사용한다. 서버 동기화 RPC는 후속 기능이다.

## 구현 순서

1. 통합 보기부터: 기존 Dock + 사용자 선택/저장/오프라인 슬롯. 복수 UART, CAN+UDS, 3개 이상, 서비스 전용뷰 왕복, 재접속/세대 변경과 STOP 기록을 실제 UI에서 검증한다.
2. Task/Step와 실행자 계약: 사용자 요청 등록·단계·도구 영수증·대기·취소/ACK를 연결한다. 재접속·중복·역순 및 완료/취소 경합을 검증한다.
3. 에이전트 작업 탭: 목록/상세·개입 배지·근거에서 통합 패널로 이동. 탭을 닫거나 바꿔도 실행과 관측이 유지되는지 검증한다.

목업은 외부 의존 없는 DEMO HTML이다. 실제 장치/daemon 연결이나 제품 기능 구현의 증거로 사용하지 않는다. 공식 참고와 모델별 판단은 각 설계서에 있다.

## 제공·검증·정리

ROOT가 Ego Lite에서 두 목업의 탭 전환, 서비스 조합 변경, 작업 목록→상세를 확인했다. Opus 목업은 Bench Light shell과 필요한 내부 터미널 dark를 사용한다. [Opus 통합 화면](OPUS-integrated-preview.png) / [작업 화면](OPUS-agent-preview.png), [Sol 통합 화면](SOL-integrated-preview.png) / [작업 화면](SOL-agent-preview.png). 실 데이터 연결 검증으로 확대하지 않는다.

네이티브 Opus와 Sol은 각각 전용 작업 공간 w1W/w1X에서 독립 제안했고 정상 종료 후 해당 공간을 닫았다. MAIN w8과 산출물을 보존했다. 작업용 브라우저·HTTP 서버도 종료했다.
