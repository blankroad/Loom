## Adopt / reject for this slice

All following choices are **I — Loom design recommendations**. Softing's observed parameter/PDU pairing and explicit Transmit support a compact editor; its broad service tree and cyclic control need not enter this slice. Vendor screenshots do not establish transaction identity or stale-response isolation.

| Step | Adopt concretely | Reject / reason |
|---|---|---|
| ECU and route | Persistent top strip: ECU logical target, separate route selector, link state. Expand route fields: CAN bus + Tx/Rx IDs; DoIP Ethernet channel + host + tester/ECU logical addresses; EthDiag vendor adapter label. | A single ambiguous “device” selector; changing route must not silently rename a past transaction. |
| Read entry | One Read DID editor: named fixture picker plus editable 16-bit DID, normalized hex, exact UDS PDU preview (`22 F1 90` for fixture VIN), explicit **Read**. Validate before sending. | Full service tree, ODX import affordance, security/session tools, raw arbitrary-service sender. Those expand this focused slice; a PDU preview supplies byte transparency. |
| Request/result | Keep editor and selected transaction detail close. Show decoded value beside response UDS bytes, DID, timestamp, ECU/route snapshot and fixture decoder provenance. | A global “latest VIN” card detached from the request that produced it. A synthetic decoder must not imply ODX decoding. |
| History | Compact transaction rows: time, ECU/route, DID, state, elapsed, request and final response summary. Select a row for its full response sequence and raw PDUs. | Using bus-frame rows as the only history; losing intermediate pending responses; replacing raw bytes with a green success badge. |
| Errors | Explicit Waiting → Pending → Positive, NRC, Timeout or Cancelled states. Keep each `7F 22 78` event; final negative response retains its raw bytes and NRC label. Timeout has no invented response bytes. | Treating response-pending as final failure; claiming successful decoding after NRC/timeout; automatic retry. Exact mock state presentation is our decision, not a verified vendor UI. |

For stale-data safety, pin target/route at Read time. Only confirmed positive data can update a value for that transaction. Cancelled/late responses must remain scoped to their original request and cannot overwrite a newer selection. Keep error text adjacent to raw evidence; do not diagnose every timeout as a disconnected cable.

## Transport boundary and synthesis recommendation

Relevant prior-plan reading only: `work/plans/simulator-ui/uds/PLAN.md` §1.4 and transport/cross-module limitations. Native UDS currently supports **DoIP only**; CAN ISO-TP and EthDiag are unsupported there. The existing Ethernet simulation is independent of the UDS loopback DoIP entity. Accordingly, label all three routes **local mock routes**, label raw data **UDS PDU**, and provide no fabricated ISO-TP segmentation, Ethernet frames, correlated capture or proprietary EthDiag framing. EthDiag is not standard DoIP.

Recommended single composition: target/route strip → compact Read DID editor → transaction history beside selected response/decoded detail, with a small SIM-options disclosure for deterministic positive/NRC/pending/timeout/cancel paths. Preserve dense engineering evidence, omit broader service navigation and gauges. Softing supplies an observed request/parameter/raw/value precedent; the exact arrangement and transaction model remain our own design choices.
