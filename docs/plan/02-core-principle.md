# 최우선 원칙 — 모든 팀, 모든 에이전트 필수 (사용자 재지시, 2026-11-09)

> **에이전트가 장비에 직접 접근해서 데이터를 읽고, 쓰고, 그 데이터를 사용자에게 실시간으로 보여준다.**
> 이것이 Loom의 존재 이유이며 가장 중요한 요구사항이다. 다른 모든 기능은 이 루프를 위한 부수 기능이다.

## 핵심 루프 (4요소 — 하나라도 빠지면 실패)

1. **직접 접근** — 에이전트가 사람 손을 거치지 않고 실제 장비(COM 포트, CAN 인터페이스, DoIP/CAN-TP ECU, 기타 장비)를 연다.
2. **읽기** — 에이전트가 장비에서 나온 데이터를 경계 있는 명령으로 읽고 해석한다.
3. **쓰기** — 에이전트가 장비에 입력/프레임/요청을 보낸다 (안전 규칙 안에서).
4. **사용자 실시간 표시** — 사용자는 **같은 데이터를 같은 순간에** 본다. 에이전트가 보낸 것과 장비가 응답한 것 모두, 출처(agent/user/device) 표시와 함께. 사후 로그 열람이 아니라 라이브 화면이다. 사용자는 보는 도중 직접 개입(입력/송신)도 할 수 있어야 한다.

## 계획서가 반드시 만족할 것 (리드가 R3/R4에서 검증)

- [ ] `plan.md` 맨 앞에 **"핵심 루프" 절**: 이 컴포넌트에서 4요소가 각각 무엇으로 구현되는지 한 표로.
- [ ] **종단 간 시나리오 1개 이상**: "에이전트가 X를 보냄 → 장비가 Y로 응답 → 사용자 화면에 Z가 몇 ms 안에 뜸 → 사용자가 W로 개입"을 구체적 명령과 화면으로.
- [ ] **실시간성 목표치**: 장비 이벤트 → 사용자 화면 표시 지연 목표(예: UART < 100 ms, CAN 트레이스 < 200 ms)와 고부하 시 동작(버스 부하 100%, 고속 UART 로그 폭주)에서도 화면이 멈추거나 거짓말하지 않는 방법(드롭 표시, 다운샘플링 명시).
- [ ] **M1 = 걷는 뼈대(walking skeleton)**: 첫 마일스톤은 시뮬레이션 백엔드 위에서 4요소가 모두 최소 형태로 동작하는 것. 부가 기능(멋진 UI, DB 포맷 다수 지원 등)은 M1 이후.
- [ ] **사용자 화면이 에이전트 세션과 분리되지 않음**: 에이전트가 장비를 쓰는 동안 사용자가 뷰어를 열면 즉시 같은 스트림이 보인다. 에이전트 전용 숨은 연결 금지.
- [ ] 이 원칙에 기여하지 않는 기능은 "후순위" 또는 "비범위"로 명시.

## 리드에게

- 진행 중인 라운드가 있어도 **지금 바로** 두 워커에게 이 문서를 읽으라고 전달하고, 이미 쓴 초안이 이 기준을 만족하는지 스스로 점검·보완하게 할 것.
- 이후 모든 작업 지시 파일(`tasks/*.md`) 첫 줄에 "docs/plan/02-core-principle.md 준수"를 넣을 것.
- 최종 `plan.md`가 위 체크리스트를 통과하지 못하면 DONE으로 표시하지 말 것.
