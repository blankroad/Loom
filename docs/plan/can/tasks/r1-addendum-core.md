# R1 긴급 추가 지시 (작업 중이어도 지금 반영)

사용자가 재지시했다. `docs/plan/02-core-principle.md`를 지금 읽어라. 브리프보다 우선한다.

핵심: **에이전트가 CAN 장비에 직접 접근해 읽고 쓰며, 사용자는 같은 데이터를 같은 순간에 라이브로 본다 (출처 agent/user/device 표시, 사용자 직접 개입 가능).**

진행 중인 R1 초안(`docs/plan/can/r1-opus.md` 또는 `r1-sol.md`)에 다음을 반영한다:

1. 문서 맨 앞(절 1 앞)에 **"0. 핵심 루프"** 절: 4요소(직접 접근 / 읽기 / 쓰기 / 사용자 실시간 표시)가 CAN 컴포넌트에서 각각 무엇(명령, 데몬 구성요소, 뷰어 화면)으로 구현되는지 한 표.
2. **종단 간 시나리오 1개 이상**: "에이전트가 `loom can send ...` → 가짜 ECU/실ECU가 응답 → 사용자 Trace/Graphics에 N ms 안에 agent/device 색으로 표시 → 사용자가 IG 패널/TUI에서 직접 송신해 개입 → 에이전트가 그 사용자 프레임도 origin=user로 읽음" 수준으로 구체 명령과 화면.
3. **실시간성 목표치**: 장비 이벤트 → 사용자 화면 지연 목표 (CAN 트레이스 < 200 ms, 플롯 갱신 등) + 고부하(버스 부하 100%, 수천~수만 fps) 시 화면이 멈추거나 거짓말하지 않는 방법: 배칭, 드롭 발생 시 "N 프레임 생략" 명시 표시, 다운샘플링 명시, 기록(파일)은 무손실 유지 등.
4. **M1 = walking skeleton**: 첫 마일스톤은 virtual 백엔드 위에서 4요소가 최소 형태로 모두 동작 (데몬 + `loom can send/trace` + 라이브 TUI 또는 웹 트레이스 + 사용자 송신). DBC 고급 기능, 다수 포맷, 멋진 UI, CANoe 제어 등은 M1 이후로 미룬다. 마일스톤/작업분해 재정렬.
5. **사용자 화면이 에이전트 세션과 분리되지 않음**: 에이전트가 버스를 쓰는 중 사용자가 뷰어를 열면 즉시 같은 스트림(최근 버퍼 포함)이 보인다. 에이전트 전용 숨은 연결 금지 — 설계에 명시.
6. 이 원칙에 기여하지 않는 기능은 "후순위" 또는 "비범위"로 명시 (절 1, 11에서).
