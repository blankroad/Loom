# R4 최종 점검 — can-sol

## 점검 기준
1. `docs/plan/02-core-principle.md`의 6개 체크 항목 — 각각 통과/미흡, 근거 절 번호. 형식적 존재가 아니라 실제로 기준을 만족하는지(예: 종단 간 시나리오에 명령·화면·지연이 다 있는지, M1이 정말 4요소를 모두 포함하는지).
2. `docs/plan/00-brief.md` §4의 15개 절 — 각각 존재·충분성.
3. `docs/plan/can/brief.md` "꼭 다룰 것" 항목별 누락 여부.
4. **사실 정확성**: 버전·라이선스·API·드라이버 동작·실측 수치 인용이 당신의 R1/R2 조사(`spikes/can/*`)와 일치하는지. 특히 §3.1 근거 수치, §6.2 BLF 수치, §7 표, §7.1, §8, §8.1, §10.5, §10.6.
5. **내부 모순**: 절 사이 수치·기본값·마일스톤 배치가 서로 어긋나는 곳 (예: §3.8 목표 vs §11 수용 기준, §10.2 등급 vs §4.3 위험 열, §15.2 vs `_xteam/can-uds-isotp.md`의 `## can 의견`).
6. 결정 기록(§16)에서 근거가 약하거나 당신이 강하게 반대하는 결정 — 반대 이유와 대안 (짧게).
