# R2 교차 리뷰 공통 지시

상대 워커의 R1 초안을 읽고 리뷰를 쓴다. 자기 초안을 고치는 라운드가 아니다 (자기 초안은 수정하지 말 것).

## 읽을 것
- 상대 초안 (아래 개별 지시 참조) 전체
- 기준: `docs/plan/02-core-principle.md`, `docs/plan/00-brief.md` §3·§4, `docs/plan/can/brief.md`
- 타팀 계약: `docs/plan/_xteam/can-uds-isotp.md` (UDS 리드 v0.1), `docs/plan/_xteam/viz-requirements.md`

## 리뷰 형식 (한국어, 마크다운)
1. **요약 판정** (5줄 이내): 상대 초안의 가장 강한 점 3개, 가장 약한 점 3개.
2. **핵심 원칙 체크리스트 점검**: 02-core-principle.md 6개 항목 각각 통과/미흡 + 근거(절 번호).
3. **틀린 사실**: 라이브러리 버전·API·라이선스·플랫폼·드라이버 동작 등. 각 항목에 "상대 주장 → 실제(근거: URL/소스 파일:줄/측정)". 확인 못 하면 "의심(미확인)"으로 구분.
4. **빠진 것**: 15개 절 중 부족한 부분, 브리프 "꼭 다룰 것" 중 누락.
5. **더 나은 선택 (상대 vs 나)**: 결정이 갈리는 지점마다 표 — 쟁점 / 상대 안 / 내 안 / 추천 / 이유. (예: 데몬 구조, IPC, 뷰어 기술, 주기 송신 방식, 기록 포맷/저널, M1 범위, ISO-TP API 형태, 위험 등급, 스킬 구조)
6. **합의 가능한 부분**: 그대로 plan.md에 채택해도 될 것.
7. **_xteam/can-uds-isotp.md 미결 질문 8개 항목(§8 1~5 등)에 대한 내 최종 의견** 짧게.

분량: 150~400줄. 근거 없는 취향 비판은 빼고, 리드가 결정하는 데 필요한 정보만.
