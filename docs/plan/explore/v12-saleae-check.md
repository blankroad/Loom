# Saleae Logic 2 자동화 사실 확인
확인일: 2026-11-10. 공식 웹 자료만 확인했으며 설치·앱 실행·실장비 시험은 하지 않았다.

1. **패키지·환경** — PyPI 최신은 `logic2-automation 1.0.11`(2025-11-18), Python 메타데이터는 `>=3.7`이며 모든 Python 버전의 동작 보장은 아니다. 라이선스는 Apache-2.0. [PyPI](https://pypi.org/project/logic2-automation/) · [메타데이터](https://pypi.org/pypi/logic2-automation/json) · [LICENSE](https://raw.githubusercontent.com/saleae/logic2-automation/master/LICENSE)
   Logic 2 공식 OS: Windows 10/11 x64, macOS 12+ Intel/Apple Silicon, Ubuntu 20.04+ 64-bit 등. Linux x64 AppImage 제공. [지원 OS](https://www.saleae.com/support/logic-software/download-and-installation/supported-operating-systems) · [배포](https://discuss.saleae.com/t/logic-2-4-48/3820)

2. **연결·headless** — 앱을 `--automation`으로 시작하고 `Manager.connect(port=10430)`으로 연결한다. 포트 변경은 `--automation --automationPort N`; GUI 설정에서도 서버 활성화 가능. `Manager.launch(application_path=...)`는 GUI 앱을 시작하고 관리하며, Manager 종료 시 앱도 종료한다. [실행 옵션](https://docs.saleae.com/automation/guides/launching-logic2) · [Manager](https://docs.saleae.com/automation/api/automation/Manager)
   **진짜 headless도 별도 프리뷰로 존재**: 공급자 배포 1.1.0 및 후속 MSO용 1.2.0에서 `Manager.launch(headless=True)`가 네이티브 서버를 실행한다. 서버를 직접 띄운 뒤 `Manager.connect()`도 가능. PyPI 1.0.11의 공개 launch 시그니처에는 이 옵션이 없다. [headless 발표](https://discuss.saleae.com/t/headless-logic2-automation-support/3793) · [1.2.0 프리뷰](https://discuss.saleae.com/t/headless-logic2-automartion-support-for-logic-mso/3798)

3. **캡처·읽기 한계** — `ManualCaptureMode`(looping, `stop()`), `TimedCaptureMode(duration_seconds=...)`, `DigitalTriggerCaptureMode`(에지/펄스·연계 채널 조건, `wait()`) 지원. [설정](https://docs.saleae.com/automation/api/automation/CaptureConfiguration) · [트리거](https://docs.saleae.com/automation/api/automation/DigitalTriggerCaptureMode)
   안정판 공개 API에는 진행 중 raw 데이터 스트림·부분 읽기 메서드가 없고, Capture 문서는 다른 작업 전에 `wait()` 또는 `stop()`을 요구한다. 공급자도 실시간 입력 읽기 API 부재를 확인했다. USB→앱 스트리밍과 외부 API 스트리밍은 별개다. [Capture](https://docs.saleae.com/automation/api/automation/Capture) · [공급자 답변](https://discuss.saleae.com/t/api-for-real-time-logging/3591)
   공통 고정 최대 시간은 명시되지 않았다. 길이는 RAM·채널·샘플레이트·디지털 전이 밀도에 좌우되며 `CaptureConfiguration(buffer_size_megabytes=...)`로 버퍼를 설정한다. Looping은 오래된 데이터를 버리고 계속 기록하며, Timed/Trigger는 메모리 부족으로 조기 종료할 수 있다. [기록 길이](https://www.saleae.com/support/logic-software/capturing-data/how-long-can-i-record-data) · [모드](https://www.saleae.com/support/logic-software/capturing-data/capture-modes) · [버퍼 오류](https://www.saleae.com/support/troubleshooting/capture-and-recording-issues/capture-stopped-error)

4. **내보내기·분석기** — `export_raw_data_csv(directory, digital_channels=..., analog_channels=...)`는 digital.csv/analog.csv, `export_raw_data_binary(...)`는 채널별 .bin, `export_data_table(filepath, analyzers, columns=..., filter=...)`은 분석기 결과 CSV 표를 만든다. 안정판 문서상 캡처 종료 후 호출한다. [Capture API](https://docs.saleae.com/automation/api/automation/Capture)
   디지털 binary v0는 초기 상태·시작/끝 시간·전이 개수와 `double` 전이 시각 목록으로 구성된다(샘플마다 저장하는 형식 아님). 아날로그는 샘플레이트와 float 샘플 배열. [공식 binary 규격](https://www.saleae.com/support/logic-software/saving-and-exporting-data/binary-export-format-logic-2)
   `add_analyzer(name, settings=...)`의 이름·키·선택 문자열은 GUI와 정확히 일치해야 한다. `SPI`: `MISO`, `MOSI`, `Clock`, `Enable`, `Bits per Transfer`(예: `8 Bits per Transfer (Standard)`). [API](https://docs.saleae.com/automation/api/automation/Capture) · [SPI 예제](https://docs.saleae.com/automation/guides/getting-started)
   `I2C`: `SDA`, `SCL`. `Async Serial`: `Input Channel`, `Bit Rate (Bits/s)`, `Bits per Frame`, `Stop Bits`, `Parity Bit` 등. [I2C 설정 소스](https://raw.githubusercontent.com/saleae/i2c-analyzer/master/src/I2cAnalyzerSettings.cpp) · [Serial 공식 설명](https://github.com/saleae/gitbook-docs/blob/master/product/user-guide/protocol-analyzers/analyzer-user-guides/using-async-serial.md)
   `CAN`: 채널 키는 **`CAN`**이며 `Bit Rate (Bits/s)`, `Inverted (CAN High)` 사용. [공식 자동화 테스트](https://github.com/saleae/logic2-automation/blob/develop/python/tests/analyzer_test.py)
   HLA는 **High Level Analyzer(Python)**이며 저수준은 LLA(C++). `add_high_level_analyzer(extension_directory, name, input_analyzer, settings=...)` 지원; LLA는 `add_analyzer`로 추가한다. [API](https://docs.saleae.com/automation/api/automation/Capture) · [공급자 용어·제한 설명](https://discuss.saleae.com/t/realtime-hla-frame-inspection-when-using-automation-api/2957)
   주의: 2.4.48에는 “캡처 중 API로 분석기 추가 시 반환이 멈추던 문제” 수정이 있다. 기존 Capture 문서의 종료 후 작업 규칙과 차이가 있으므로 최신 앱에서 진행 중 분석기/HLA 사용 범위는 **미확인**이며, raw 스트리밍 지원의 근거로 볼 수 없다. [2.4.48 변경 기록](https://discuss.saleae.com/t/logic-2-4-48/3820)

5. **시뮬레이션·CI** — 공식 확인 ID는 `F4241` = Logic Pro 16 demo. 전체 고정 ID 목록은 **미확인**; `manager.get_devices(include_simulation_devices=True)`로 열거한다. 데모 raw는 실제 SPI 데이터가 아니라는 예제 주석도 있다. [예제](https://docs.saleae.com/automation/guides/getting-started) · [장치 열거](https://docs.saleae.com/automation/api/automation/Manager)
   실장비 없는 캡처 예제가 있으므로 시뮬레이션 CI가 가능하나, 안정판 경로에는 Logic 2 앱이 필요하다. 공식 Ubuntu 예제는 Xvfb에서 AppImage 실행이다. 네이티브 headless 프리뷰에도 F4241 예제가 있으나 이 조사에서 CI 실행은 검증하지 않았다. [Xvfb](https://docs.saleae.com/automation/guides/getting-started#headless-on-linux) · [headless 예제](https://discuss.saleae.com/t/headless-logic2-automation-support/3793)

6. **하드웨어** — Logic 2 GUI는 Logic 8/Pro 8/Pro 16 및 단종 Original Logic(8ch)/Logic16/Logic 4를 지원한다. Logic 4는 1세대가 아니라 2세대다. [연결 안내](https://new.saleae.com/support/logic-software/capturing-data/connecting-the-logic-hardware) · [세대 구분](https://www.saleae.com/support/specifications-hardware/electrical-characteristics/device-calibration)
   자동화의 `DeviceType`에는 위 6종 enum이 있으나 `LogicDeviceConfiguration` 설명은 Logic 8/Pro 8/Pro 16만 명시한다. 구형 3종의 자동화 보장 범위는 **미확인**. 네이티브 headless 1.1.0 프리뷰는 신형 3종만 지원한다고 명시한다. [enum](https://docs.saleae.com/automation/api/automation/DeviceType) · [설정 클래스](https://docs.saleae.com/automation/api/automation/LogicDeviceConfiguration) · [프리뷰 제한](https://discuss.saleae.com/t/headless-logic2-automation-support/3793)

7. **sigrok** — 신형 전체가 미지원이라는 단정은 틀리다. Logic 8은 planned; Pro 16은 supported이지만 **실험적·디지털 전용** `saleae-logic-pro` 드라이버다. Pro 8 문서는 planned와 실험적 구현 설명이 혼재하며 현재 드라이버는 Pro 16 VID/PID만 열거하므로 Pro 8 지원은 보장할 수 없다. [Logic 8](https://sigrok.org/wiki/Saleae_Logic8) · [Pro 16](https://sigrok.org/wiki/Saleae_Logic_Pro_16) · [Pro 8](https://sigrok.org/wiki/Saleae_Logic_Pro_8) · [드라이버 소스](https://raw.githubusercontent.com/sigrokproject/libsigrok/master/src/hardware/saleae-logic-pro/api.c)
   Original Logic(FX2LP)은 `fx2lafw`로 지원, 구형 Logic16은 별도 `saleae-logic16`으로 지원하며 공급자 펌웨어/FPGA bitstream 추출이 필요하다. Pro 16도 공급자 펌웨어 추출이 필요하고 최신 하드웨어 리비전 호환은 **미확인**. [Original](https://sigrok.org/wiki/Saleae_Logic) · [Logic16](https://sigrok.org/wiki/Saleae_Logic16) · [Pro 16 펌웨어](https://sigrok.org/wiki/Saleae_Logic_Pro_16#Firmware)

8. **GUI 동시 사용·연결 수** — 같은 GUI 앱에 연결할 수는 있지만 자동화 캡처 중 파형 화면의 실시간 갱신 여부는 **미확인**. 공급자는 자동화를 실시간 관찰·사용자 조작 병행 용도로 설계하지 않았다고 설명한다. 따라서 “사용자가 자동화 중 실시간 파형을 본다”는 계획 전제로 확정할 수 없다. [공급자 답변](https://discuss.saleae.com/t/python-automation-api-zooming-out-from-script/3405)
   자동화 클라이언트 동시 연결의 최대 개수·중재 규칙은 공개 문서에서 **미확인**(1개 제한도 확인되지 않음). 장치 수·앱 인스턴스 수와 혼동하지 말 것. [Manager 문서](https://docs.saleae.com/automation/api/automation/Manager)

9. **Linux 조건** — 실장비 USB 접근에는 `99-SaleaeLogic.rules` udev 규칙이 필요하며 앱이 누락 시 설치를 안내한다. 네이티브 headless 서버도 규칙 설치가 필요하다. [드라이버 설치](https://www.saleae.com/support/logic-software/download-and-installation/driver-install) · [headless 요구사항](https://discuss.saleae.com/t/headless-logic2-automation-support/3793)
   안정판 GUI CI의 공식 Ubuntu 20.04 예제 의존성은 `xvfb libatk1.0-0 libatk-bridge2.0-0 libgtk-3-0 libgbm1`. AppImage 실행 권한과 FUSE 2(`libfuse2`)가 필요할 수 있고, 추출 실행도 안내한다. Ubuntu 24.04는 AppArmor 프로필 또는 공급자 안내의 `--no-sandbox` 우회가 필요할 수 있다. [Xvfb 의존성](https://docs.saleae.com/automation/guides/getting-started#headless-on-linux) · [AppImage 설치](https://www.saleae.com/support/logic-software/download-and-installation/sw-installation) · [FUSE 설명](https://www.saleae.com/support/troubleshooting/installation-and-launch-issues/fails-to-launch)
