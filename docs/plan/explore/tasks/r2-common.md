# explore R2 — 교차 리뷰 공통 지시

목적: 상대 워커의 R1 초안을 비판적으로 리뷰해, 리드가 R3에서 통합할 근거를 만든다. 계획 단계, 구현 금지.

## 입력
- docs/plan/explore/r1-opus.md, docs/plan/explore/r1-sol.md (둘 다 읽되, 리뷰 대상은 상대 것)
- 최우선 기준: docs/plan/02-core-principle.md
- 기준: docs/plan/00-brief.md §3(공통 계약), docs/plan/explore/brief.md, docs/plan/explore/tasks/r1-common.md(절 구조)
- 중복 확인: docs/plan/uart, can, uds 폴더의 최신 초안(있으면)과 docs/plan/_xteam/

## 리뷰 파일 구성 (한국어, 아래 순서로 절 제목 유지)
1. **틀린 사실** — 라이브러리 버전/라이선스/플랫폼/API/프로토콜 사실 오류. 각 항목에 근거(URL, PyPI 확인, 스파이크 결과)와 확신도(높음/중간/낮음).
2. **평가 이견** — 상대 평가표에서 점수·순위가 잘못됐다고 보는 후보. 특히 핵심 루프 4요소 판정(○△✗)이 과대/과소 평가된 것. 후보 / 상대 판정 / 내 판정 / 근거.
3. **빠진 것** — 빠진 후보, 브리프 산출물 5개 항목 중 누락·얕은 부분, 상위 추천 소절 a~j 중 빠진 요소.
4. **더 나은 선택** — 상위 추천 목록, 플러그인 구조, 교차 기능(시나리오 러너/통합 타임라인) 처리 방식에서 상대 안보다 낫다고 보는 설계. 비교표(기준: 핵심 루프 가치, 단순성, 구현 비용, HW 확보, Windows/macOS, 기존 3팀과의 경계)와 추천.
5. **합의 가능한 부분** — 그대로 채택해도 되는 상대 안의 좋은 아이디어 (내 초안보다 나은 점은 솔직하게 인정).
6. **핵심 원칙 점검** — 상대의 상위 추천 각각이 02-core-principle.md 체크리스트 6개를 실제로 만족하는지 (충족/부분/미충족)와 보완안. 지연 목표의 근거, 고부하 시 화면 동작, M1 범위의 현실성.
7. **쟁점 목록** — 리드가 결정할 미해결 쟁점 표: 쟁점 / opus 안 / sol 안 / 내 추천 / 근거. 특히 "최종 상위 3~5개와 순서"에 대한 내 추천을 반드시 포함.
