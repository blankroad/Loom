# UART R2 — 교차 리뷰 공통 지시

목적: 상대 워커의 R1 초안을 비판적으로 리뷰해, 리드가 R3에서 통합할 근거를 만든다. 계획 단계, 구현 금지.

## 입력
- docs/plan/uart/r1-opus.md, docs/plan/uart/r1-sol.md (둘 다 읽되, 리뷰 대상은 상대 것)
- 최우선 기준: docs/plan/02-core-principle.md
- 기준: docs/plan/00-brief.md §3(공통 계약), §4(15개 절), docs/plan/uart/brief.md

## 리뷰 파일 구성 (한국어, 아래 순서로 절 제목 유지)
1. **틀린 사실** — 라이브러리 버전/라이선스/플랫폼 동작/API 등 사실 오류. 각 항목에 근거(문서 URL, 확인 방법, 스파이크 결과)와 확신도(높음/중간/낮음).
2. **빠진 것** — 브리프 요구사항이나 §4 절 중 누락·얕은 부분. 무엇을 추가해야 하는지 구체적으로.
3. **더 나은 선택** — 상대 안보다 낫다고 보는 설계 선택. 내 안 vs 상대 안 비교표(기준: 단순성, 안정성, 에이전트 사용성, 사용자 가시성, Windows 호환, 구현 비용)와 추천.
4. **합의 가능한 부분** — 그대로 채택해도 되는 상대 안의 좋은 아이디어 (내 초안보다 나은 점은 솔직하게 인정).
5. **핵심 원칙 점검** — 상대 초안이 docs/plan/02-core-principle.md 체크리스트 6개 항목을 실제로 만족하는지 항목별 판정(충족/부분/미충족)과 보완안. 특히 실시간 지연 목표의 근거, 고부하 시 화면 동작, M1 걷는 뼈대 범위의 현실성.
6. **쟁점 목록** — 리드가 결정해야 할 미해결 쟁점을 표로: 쟁점 / opus 안 / sol 안 / 내 추천 / 근거.

## 규칙
- 파일 쓰기는 docs/plan/uart/ 와 spikes/uart/ 만. 사실 확인용 짧은 스파이크는 허용.
- 자기 R1 파일은 수정하지 말 것 (리뷰 파일에만 쓴다).
- 완료되면 화면에 "R2 DONE: <파일경로>" 한 줄만 출력하고 멈춘다.
