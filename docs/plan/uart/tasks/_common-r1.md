# UART R1 공통 지시 (두 워커 공통)

역할: 당신은 Loom 프로젝트 UART 컴포넌트의 계획 워커다. 리드는 uart-lead.
**계획 단계다. 구현 코드 작성 금지.** (스파이크 예외: spikes/uart/ 안에서 짧은 검증 코드만, 전역 설치 금지, 필요하면 spikes/uart/.venv)

## 산출물
- 00-brief.md §4의 **15개 절 전체**를 포함하는 계획 초안. 한국어로 작성. 각 절 제목은 "## 1. 범위 / 비범위" 처럼 번호를 붙인다.
- 절마다 구체적으로: CLI 명령은 실제 인자와 출력 예시, 화면은 ASCII 목업, 포맷은 필드 정의 예시까지.
- 근거를 확인한 사실과 추정을 구분해 표시한다 (예: "[확인: PyPI 2026-xx]", "[추정]").
- 결정이 필요한 쟁점은 대안을 2개 이상 비교하고 추천안을 적는다.

## 반드시 다룰 쟁점 (빠뜨리지 말 것)
- 데몬 1개가 포트를 소유, 에이전트 CLI와 사용자 TUI 뷰어가 동시에 클라이언트로 붙는 구조. 다중 포트 동시 세션.
- 사용자 입력과 에이전트 입력이 섞일 때의 규칙 (락/우선순위/출처 표시/사용자 타이핑 중 에이전트 send 처리).
- 포트 탐색(VID/PID, 설명), 시리얼 파라미터, USB-시리얼 뽑았다 꽂기 재연결(같은 장치 식별 방법 포함).
- 에이전트 동작: send (문자열/hex/파일, 줄끝 CR/LF/CRLF), read --tail/--since, expect regex --timeout, 버퍼 커서(에이전트별 "마지막으로 본 이후"), 바이너리/ANSI 처리, 출력 크기 상한.
- 사용자 뷰어: herdr 패인에서 `loom uart attach COM3`. 타임스탬프 토글, hex 보기, 에이전트 송신 강조, 스크롤백 검색, 로그 저장, 키 입력 그대로 전달(Ctrl-C, 뷰어 자체 탈출키 규칙), 웹 뷰 검토.
- break 신호, DTR/RTS 토글(리셋/부트모드 시퀀스), XMODEM/YMODEM 범위 판단.
- 기록: 원시 바이트+타임스탬프, 줄 단위 텍스트 로그, 공통 이벤트 레코드(00-brief §3-6) 매핑. viz 요구사항(숫자 추출 플롯) — 이 절은 계획서 안에 "viz 요구사항 초안"으로 적어두면 리드가 _xteam 파일에 옮긴다.
- 시뮬레이션: pty/가상 포트 페어(macOS/Linux socat·pty, Windows com0com 등), 가짜 디바이스 스크립트(부팅 로그, 로그인, 쉘 프롬프트), HW 없는 CI.
- IPC 프로토콜 제안 (00-brief §3-3: 요청/응답 + 이벤트 스트림, 웹 뷰어 직접 접속 유리). 메인이 확정하므로 근거와 함께 제안.
- 스킬 패키징: .claude/skills/loom-uart/SKILL.md (짧게) + references. Codex 호환.
- 안전: 위험 등급, 사용자 확인, 레이트 제한, 위험 명령(예: 부트로더 진입, 펌웨어 쓰기 명령 문자열) 처리.
- 작업 분해(§12)는 병렬 가능한 단위로, 각 작업에 추천 담당(Opus 워커 / Sol 워커)과 의존성 표시.

## 규칙
